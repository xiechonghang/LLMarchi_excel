# M1 图示阅读反馈02：计算框、张量箭头与源码命名

2026-10-18，用户实际检查新图后提出两项问题：框内文字颜色无法看清；图中难以区分tensor传输与计算。用户希望类似ONNX计算图：除开头hidden states输入，框表示执行计算的算子，tensor或权重作为箭头上的传输信息；算子和tensor采用源码名称，计算框还标注MatMul、ADD、Mul、Softmax等类型，tensor标注size维度。

本次反馈是HTML展示要求的明确化。旧5411静态工程通过只属于原已记录覆盖，不能据此否认用户的颜色和图义问题；新图阅读未通过。用户先前对算子粒度和Excel内容的认可保留，冗余以后讨论，本轮不清理Excel或重拆算子，不进入M2/M3。

对应修改与完成标准：

- 图中文字/副标题/类型/边标签在浅色和深色主题都有匹配的文字与底色，不能只在浅框上套用深色页面的浅色文字；可读性需明确检查，静态配色不代签真实浏览器视觉。
- 计算图中的矩形计算框只表示真实算子，开头hidden_states允许作为明确输入标识。中间activation、权重、mask、索引和cache的前/后状态不再画成类似计算框；在真实有向箭头上标源码张量名和shape，图外输入/输出可用无计算框的端口/箭头引入，不能丢实际依赖。
- 框内采用源码中的模块/函数/调用表达式名称，并单列实际计算类型。已认可的复合粒度保留，复合类型如Linear + View + Transpose如实列出，不能为模仿ONNX导出而重写模型或引入新框架。
- 同一源码变量在不同步骤被复用时，可加局部上下文/版本后缀区分，但明确它是图内消歧；无法找到独立变量的表达式中间值直接标源码表达式，不能把提取器内部id冒称源码变量。保留原id/源码位置联查。
- 张量和权重的连接、维度、分支/残差/共享、缓存历史/本次可读视图/持久回写条件继续来自已核阅读数据；只做展示标签映射，不复制第二份连接或shape事实。JSON、effective_config和Excel应保持原字节。
