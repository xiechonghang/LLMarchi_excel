## 已确认规则

1. batch size 固定为 1。`n` 默认 1；存在 head 维度的算子用它表示适用的 head 数，不能兼作层数、执行次数或专家数。其他分组/重复因子依据实际算子映射，明确落入维度或工作量，不塞入 n。
2. `T seqlen or N`：可表达 seqlen、CUBE 左矩阵 M 方向或 VEC 行数。`hiddensize or D`：可表达 hidden size、CUBE K 方向或 VEC 列数。每行按算子语义映射，不机械套用全局 hidden size。
3. 两种吞吐均以 `element/ms` 呈现。CUBE 工作量沿用 M×K×N 的乘积口径，不额外乘 2；VEC 工作量按 n×T×D。CUBE 存在独立 head/矩阵 batch 时，将既有批量因子计入有效 M/工作量一次，并在简短维度说明中解释折算；不能丢 head 或再次乘 head。
4. CUBE 使用 cube perf，VEC 使用 vector perf，两者是独立可编辑输入。草稿的示意吞吐值不替代现有默认吞吐约定；默认数值沿用现有 4096/64，仅改变新表的单位展示与公式组织。
5. 每行代表一个算子任务。纯 CUBE 行的 VEC 项为 0，纯 VEC 行的 CUBE 项为 0；`op(ms)=MAX(cube(ms),vector(ms))`。缺失必要输入或未知成本不能用 0 代替。
6. 单行复合算子复用已核验的多项工作量规则，同一op的矩阵项按SUM/重复次数合成CUBE工作量，各项放辅助明细；不能只取第一项或对多项取MAX。MAX仅用于最终CUBE与VEC耗时。不得把语义上不同的算子合成一行，也不得为填满模板引入新的计费项。
7. 草稿层数全为 10、q_a_norm 维度等均为示意。真实层型、算子清单、head 数、维度、条件分支和层数来自源码/config及已有结构数据。
8. 算子模板只计一次；单层汇总、真实层数与整网汇总的乘法清楚可查。共用通路复用不代表不同真实层不发生计算，父子明细和总计不可重复加总。

## 呈现建议

- 工作表顶部：左侧为集中参数区，右侧为独立硬件吞吐区。参数按场景、真实结构层数、基础维度、Attention/Indexer、MoE/FFN、mHC等归类；只展示实际适用项。
- 主表 12 列：结构/通路、op、op type、n、T seqlen or N、hiddensize or D、M、K、N、cube(ms)、vector(ms)、op(ms)。头数 n 与矩阵输出维 N 的列名大小写保持清楚。
- 算子按真实 Q/KV/O、SWA/CSA/HCA、路由/共享与路由专家、Dense FFN、mHC等通路组织，具体区块取决于真实结构。使用真实顺序与短标签，不照抄草稿预留区。
- 保留有用的维度中间值与活公式，参数集中引用；区分跨场景可共用常量与各场景派生值。
- 源码定位、完整 shape、内部 id、长说明和复杂项分解放在辅助明细，不挤入主表。明细是可追溯依据，不改变成本。
- 白底黑字、紧凑行高、适量细边框与轻量分区。以草稿宋体 11 磅为参考并检查目标环境显示；输入提示、数值格式、冻结窗格以可读性为准。长说明不溢出主表。
- 新表保留 Prefill/Decode 两场景；顶部保留 seqlen/kvcachelen，batch=1清楚标注。硬件能力修改应驱动相应耗时更新。
