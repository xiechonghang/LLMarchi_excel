## 1. 目标与阅读重心

模型结构图应解释“数据经过哪些计算、如何流动、维度怎样变化”，尤其优先读清性能主体 Decoder 内部的 Attention、FFN、Norm、残差和必要分支。

- 保留整网 → 重复层组 → Block/模块 → 内部语义操作的逐级阅读方式，不再平铺一张无限展开的完整图。
- 优先完善从 Decoder/Block 进入内部计算路径的阅读体验；整网图仍作为入口和上下文。
- 源码与配置是结构事实依据；ONNX/onnxsim 可用于辅助联查和参考化简规则，不能替代模块身份与源码对应关系。
- 继续静态分析，不实例化或运行模型，不读取真实权重数值，不依赖指定 XPU 后端。

## 2. 已确认：节点粒度与名称

- Linear、MatMul 等计算需要清晰可辨；Linear 默认同时显示**实例名与操作类型**，例如 `kv_proj · Linear`、`q_a_proj · Linear`。
- Linear 详情保留输入/输出特征维度、权重形状、模块完整路径与源码位置。名称按实际源码取值；`q_lora_rank` 是参数，不能冒充某个 Linear 的实例名。
- Norm、RoPE、Softmax 等默认使用具名语义操作粒度，不机械拆成内部的平方、求均值、切片、乘加等全部微步骤。主图可显示类型名，详情保留实际实例与源码。
- 不能因为源码写在同一行，就把不同的具名计算合为一个不可辨认节点。以本例为准，`kv_proj` 与 `kv_norm` 应能分别读出。
- View、Transpose、Split 等不是按类型统一隐藏或删除。是否保留、合并或消除，取决于具体等价条件；没有证明时保留。

## 3. 已确认：箭头与维度名称

- 箭头表示张量数据依赖与流动方向，默认标出对应位置的张量形状；不能仅表示模块调用顺序。
- 展示使用 modeling/config 中的全称，例如 `batch_size`、`seqlen`、`hidden_size`、`head_dim`、`num_attention_heads`、`num_key_value_heads`、`q_lora_rank`、`qk_rope_head_dim`、`kvcachelen`。
- 主图不再用 `B/S/H/Dh/Rk/Rq` 作为这些参数的展示缩写。内部结构数据是否继续使用别名属于实施选择，但展示映射必须准确且可追溯。
- `seqlen` 是本次新输入长度，`kvcachelen` 是调用前的逻辑历史长度；二者不能混用。
- 固定常量可以直接显示。本例单 KV 头轴为 `1`，并说明其与当前实现及配置的关系；不能为了“参数化”虚构可任意改变的头数。
- 分支、广播、切分或多输入场景须保留各输入/输出的身份与维度，不能为了简洁抹去必要的数据关系。
- 参数、权重与源码等辅助信息按需查看，避免默认增加大量辅助连线。

## 4. 已确认：单向、紧凑的布局

- 一张图的主计算链沿一个方向按拓扑顺序展开。当前认可样式为**从上到下**，不采用来回折返的蛇形排列。
- 主链箭头不向上游回指，不用布局折返制造“数据回流”的错觉。
- 分支和残差连接向下游汇合。跨调用的缓存/递推状态应准确表达为历史状态输入与新状态输出，不能因排版隐藏依赖，也不必用回流箭头绕回输入。
- 辅助输入紧贴其实际消费节点，以短旁枝接入。例如 `cos/sin` 紧邻 RoPE，不为它设置占满图高的独立分区。
- 当前讨论稿已去掉原来的 01“位置编码输入”、02“张量接入通道”及分栏框；不保留只有空白或一个辅助输入的大块区域。
- 不以缩写参数、缩小到难读的字体、删掉必要节点或省略分支来换取紧凑；具体图允许按阅读方向延展。

## 5. 已确认：化简的含义与总边界

这里要求的是**有依据的逻辑计算图等价化简**，类似 onnxsim 对冗余结构的处理，不是按算子名称统一折叠或藏起节点。

- 每条规则都需要明确成立条件。对声明的合法输入范围保持值、形状、轴含义、数据类型和必要状态行为一致。
- 对符号 `seqlen/kvcachelen/batch_size` 的通用图，不能只因某个示例取值成立就全局应用规则。需要特化时必须明确标注场景与条件。
- 条件不能证明时保留原结构；只知道元素总数相同，不足以证明布局、索引或矩阵解释等价。
- 保留化简前后的节点、张量、模块与源码对应；中间结果存在其他使用者时，不能误删其他分支需要的节点。
- 化简结果是逻辑计算结构，不是某个编译器的最终执行图。图中有操作不等于独立 kernel，图中等价合并也不证明设备已融合或省去了实际搬运。

### 已明确批准：Transpose 并入矩阵乘语义

若能证明等价，允许将紧邻矩阵乘的 Transpose 合并进矩阵乘语义，例如直接表示为 `Q @ Kᵀ`。

- 必须明确转置的轴。最后两个矩阵轴的转置不能与 batch/head/seqlen 轴的其他置换混淆。
- 输入、输出维度仍使用全称；转置含义和原 Transpose/MatMul 的源码对应必须保留。
- 若转置结果还有其他使用者，相关分支仍保留。
- 该批准不等于允许任意计算融合，也不代表目标设备已经融合。

### 已讨论的其他候选规则

以下最初为讨论候选，现由用户的版本开发授权纳入 T12 保守白名单；成立条件、应用/拒绝原因及正反例是验收要求。无法证明就保留，不要求任意符号证明器；纳入任务不代表已实现。

1. **形状计算化简**：把用于构造 shape 的 `Shape/Gather/Concat` 等支路归纳为符号表达式；保留动态变量，不把未知规模变为某个示例常量。不折叠依赖真实权重数值的计算。
2. **恒等操作消除**：目标形状完全相同的 Reshape、恒等轴置换等；需保证数据解释不变。
3. **连续 Transpose 合并/抵消**：按真实轴置换复合，结果为恒等时可消除；保留其他使用者所需的中间分支。
4. **连续 Reshape/View 合并**：无中间计算，元素顺序、形状推导和合法输入域均满足条件时，只保留等价最终变换；不能直接跨越真实重排或切分。
5. **单位轴相关化简**：如本例 View＋Transpose 可在单 KV 头成立时改写为一个 Reshape；仍保留三维到四维的变化，不能把两步全部删掉。
6. **Split/Concat 抵消**：需要完整切分、同轴同顺序原样拼回、没有改变数据等条件；分支进入不同计算时不能直接抵消，存在其他使用者时仍保留其依赖。

### 当前不纳入的扩展

- 不因相邻就融合 `Linear → RMSNorm`、激活、RoPE、Softmax 或残差计算。
- 不擅自消除精度转换、改变数值精度或重排浮点计算来换取更少节点。
- 不依赖权重内容、实际 MoE 路由结果或特定后端优化来猜测结构。
- 不消除真实缓存读写、状态更新、条件分支或循环语义。

## 6. 已确认的 KV 示例

输入是 Attention 接收到的 `hidden_states`；本例只覆盖新 KV 准备路径，不覆盖后续缓存更新、压缩 KV 拼接与完整 Attention。

```text
hidden_states [batch_size, seqlen, hidden_size]
  → kv_proj · Linear(hidden_size → head_dim)
  → [batch_size, seqlen, head_dim]
  → RMSNorm（实际实例 kv_norm）
  → [batch_size, seqlen, head_dim]
  → View
  → [batch_size, seqlen, 1, head_dim]
  → Transpose(1, 2)
  → [batch_size, 1, seqlen, head_dim]
  → RoPE（旁枝输入 cos/sin）
  → kv [batch_size, 1, seqlen, head_dim]
```

- `kv_proj.weight` 为 `[head_dim, hidden_size]`；RMSNorm 可学习权重为 `[head_dim]`。
- 当前配置示例：`hidden_size=4096`、`head_dim=512`、`qk_rope_head_dim=64`、单 KV 头 `1`；图上保留变量全称。
- 本地建模实现对尾部 `qk_rope_head_dim` 个通道做 RoPE，输出 shape 不变。
- 同一 KV 张量后续同时作为 K、V；不能虚构成两条独立 K/V 投影。
- 此段不应把 `seqlen` 写为 `seqlen+kvcachelen`；历史长度在后续缓存/Attention 计算中出现。

来源为本地官方 Transformers 检出 `536ecc007387a50e77603bb5d92100e9b07514cc`：

- [模型实现](../../hflib/transformers/src/transformers/models/deepseek_v4/modeling_deepseek_v4.py)：787–788（投影/归一）、807–822（形状与本例调用）、339–356（RoPE）、846–850（同一 KV 送入 K/V）。
- [当前模型配置](../../models/deepseek-ai/DeepSeek-V4-Flash-0731/config.json)。
